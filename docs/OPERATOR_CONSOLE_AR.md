# واجهة مشغّل محلية للمختبر المستقل (SQLite)

هذه واجهة خفيفة مبنية على HTML خادمي، دون JavaScript طرف ثالث أو متصفح يملك
رمز API الإداري. تدعم تسجيل دخول وخروج محليين، جلسات قابلة للإبطال،
عرض التشغيلات وبحثها وتصفيتها وتقسيمها إلى صفحات، إرسال وصفة python-smoke المقبولة في التشغيل الجذري،
تفاصيل التشغيل والإيصال، وعرض نتيجة التحقق الحسابي من الإيصال.
تتحدث الواجهة مع SQLite API عبر الشبكة الداخلية؛ العامل وحده ينفذ الوصفات.

**حدود الاعتماد:** هذا دخول *مشغّل محلي واحد*، وليس حسابات متعددة أو
منظمات أو صلاحيات مشروعات أو SSO. يمنع نشر الواجهة أو API على الإنترنت،
أو وضعهما خلف وكيل عكسي عام قبل تنفيذ RBAC والخدمات الأمنية اللازمة.
فحص بصمة الإيصال لا يثبت مصدره/بيئة تشغيله ولا يمنح سلطة إغلاق أو دمج/نشر.

## التشغيل دون تغيير المسار الافتراضي

يتوافر Dockerfile الجذري أصلًا؛ وتبقى خدمات Compose الافتراضية دون تغيير.
الواجهة الجديدة خدمة اختيارية ضمن profile باسم operator-ui وعلى localhost فقط.

1. أنشئ كلمة مرور فريدة طويلة للمشغل. للتوليد، من جذر المستودع نفذ:
   python3 -m qa_lab.console hash-password
   سيطلبها بوساطة getpass ويطبع **تجزئة PBKDF2** وليس الكلمة الأصلية.
   لا تحفظ الكلمة الأصلية في Git أو Compose أو سجل الأوامر.
2. صدّر QA_UI_PASSWORD_HASH بالقيمة المطبوعة. واستخدم QA_API_TOKEN
   العشوائي الحالي، وQA_WORKSPACE_PATH لمسار checkout موثوق موجود.
   لا تشغّل الوصفات على مصادر غير موثوقة.
3. نفذ docker compose --profile operator-ui config --quiet ثم
   docker compose --profile operator-ui up -d --build.
   هذه **أوامر مقترحة للمشغل فقط** وليست تقريرًا عن نشر تم بالفعل.
4. افتح http://127.0.0.1:8780/login وسجل الدخول بكلمة المرور.
   يمكن تغيير منفذ الحلقة المحلية فقط باستخدام QA_UI_PORT.

المتصفح لا يستقبل QA_API_TOKEN. الرمز موجود كمتغير بيئة داخل خدمة
الواجهة فقط لطلب API الداخلي؛ لا يضاف إلى صفحات HTML أو الكوكيز أو
عناوين URLs. الكوكي HttpOnly; SameSite=Strict مع جلسة في ذاكرة
الخادم تنتهي بعد 30 دقيقة؛ يعطلها تسجيل الخروج فورًا. عند إعادة تشغيل
الحاوية تُلغى جميع الجلسات. حماية CSRF إلزامية لعمليات الإرسال والخروج،
مع فحص Origin عند توافره ومقاومة محدودة لمحاولات كلمات المرور.

عند استخدام HTTPS في بيئة مقيدة ومراجعة أمنيًا، يمكن ضبط
QA_UI_COOKIE_SECURE=1، لكن لا يترتب على ذلك أي تصريح بالنشر العام.
قيد Host الحالي يسمح فقط بـlocalhost و127.0.0.1 و::1. لا تعتمد على
هذه الحماية وحدها بدل firewall وشبكة مغلقة.

## API والعقد

- GET /v1/runs?status=&project=&q=&limit=25&offset=0:
  قائمة تشغيلات مرتبة بـcreated DESC ثم id DESC، بحد أقصى 100 لكل طلب،
  وإزاحة قصوى 10000. البيانات خاضعة لرمز Bearer الموجود، دون إخراج
  تفاصيل الإيصالات أو مفاتيح التكرار.
- POST /v1/runs: يرسل الطلب إلى قائمة العمل وفق القائمة البيضاء.
- GET /v1/runs/{id} وGET /v1/evidence/{id}:
  تفاصيل الحالة والتحقق من بصمة الإيصال.

الإرسال لا ينفذ مباشرة؛ العامل مستقل ويتحقق من SHA نسخة العمل وفق
السياسات الحالية. حالة FAILED ليست فشل GitHub Actions، وحالة PASSED
ليست قبول إصدار. لا توجد واجهة تنفيذ أوامر حرة ولا إغلاق حالات.

## اختبارات وحدود المرحلة التالية

تغطي tests/test_operator_console.py سلوك HTTP المحلي، الجلسات وCSRF،
وتقنين الوصفات، ومنع تسريب رمز Bearer وXSS، ورفض Host غير محلي،
وعرض الإيصالات. تغطي tests/test_run_catalog.py التصفية وحقن SQL
والتقسيم ومصادقة API. ويتحقق tests/test_console_e2e.py من المسار
الفعلي: المتصفح -> الواجهة -> API -> قاعدة SQLite -> العامل -> الإيصال
ومن كشف تغيير بصمة الإيصال. واختبار رد 302 يضمن عدم إعادة إرسال رمز
Bearer إلى جهة أخرى عند التحويل. تُضمّن ملفات CSS داخل حزمة Python. شغلهما مع مجموعة الانحدار الكاملة قبل الدمج:

python -W error::ResourceWarning -m unittest discover -s tests -v

لم يجرِ بهذه المرحلة إنشاء هويات متعددة أو RBAC أو صفحة إدارة أو قياسات
وتنبيهات إنتاجية أو اختبارات استعادة حقيقية. هذه بوابات مستقلة مطلوبة
قبل توسيع النشر خارج الجهاز المحلي.
