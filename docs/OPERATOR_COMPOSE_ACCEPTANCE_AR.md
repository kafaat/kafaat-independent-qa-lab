# قبول واجهة المشغل المحلية داخل Docker Compose

هذا المسار يختبر تشغيل الواجهة داخل حاوية حقيقية، لا مجرد اختبار HTTP محلي.
يمر عبر المتصفح ثم operator-ui ثم API ثم قائمة SQLite ثم العامل ثم إيصال
التنفيذ والتحقق الحسابي. لا يمنح نجاحه صلاحية نشر إنتاجي أو إغلاق حالات.

## ما يشترطه المجس قبل أي اتصال بـ Docker

يتطلب QA_OPERATOR_COMPOSE_OPT_IN=isolated-ci، ومصدر Git نظيفًا وملتزمًا،
وعنوان ملف الإيصال خارج checkout، واتصال Docker عبر Unix socket محلي.
يرفض تعيين DOCKER_HOST أو DOCKER_CONTEXT. يستخدم اسم مشروع مؤقتًا،
ورمز API وكلمة مرور اصطناعيين عشوائيين، ونسخة Git خاصة للقراءة فقط،
وحجم بيانات مستقلًا. لا يدير أي مشروع Docker قائم.

## حالات القبول الفعلي

- صحة إعدادات profile operator-ui، وبناء الحاويات وبدئها على حجم نظيف.
- ربط API والواجهة حصريًا بـ 127.0.0.1 ومنع منافذ عامة.
- تشغيل واجهة العرض بمستخدم غير جذري وبنظام ملفات read-only،
  ودون mounting لمجلد البيانات أو checkout في حاويتها.
- تحميل صفحة الدخول وCSS من الحاوية، ووجود ترويسات CSP وno-store.
- رفض قراءة البيانات قبل الدخول، ورفض HTTP API من دون Bearer.
- رفض كلمة مرور خاطئة وHost غير محلي وCSRF وOrigin الخاطئ.
- رفض وصفة غير معتمدة وSHA مشوه.
- إرسال python-smoke من الواجهة، وإعادة طلبه بمفتاح التكرار نفسه،
  ثم تنفيذ العامل فعليًا على SHA متطابقة مع نسخة Git الخاصة.
- ظهور نجاح الوصفة وبيانات الإيصال الصحيحة في تفاصيل التشغيل
  وفي قائمة النتائج المصفاة، وتحقق SHA256 المستقل.
- انتهاء جلسة المستخدم بعد logout وبعد إعادة تشغيل حاوية الواجهة،
  مع بقاء الإيصال قابلًا للعرض بعد تسجيل الدخول من جديد.
- تنظيف المشروع المؤقت وحجمه وشبكاته ونسخته، وثبات SHA/tree المصدر.

لا ينشر المجس خدمات إنتاجية، ولا يعيد تشغيل أي GitHub Actions
يدويًا. يجري اختبارًا مستقلًا ضمن CI عند push إلى main أو pull_request.

## التشغيل اليدوي داخل بيئة اختبار مخصصة

من نسخة Git نظيفة وعلى Linux مع Docker Compose v2 واتصال Unix محلي:

    export QA_OPERATOR_COMPOSE_OPT_IN=isolated-ci
    python scripts/verify_operator_compose.py --output /tmp/qa-operator-proof.json

تُرفع أدلة JSON ضمن GitHub Actions، بما يشمل مصدر SHA/tree،
وعلامة PASS أو FAIL، وحالات checks، وموقع المرحلة التي فشلت فقط،
دون إرسال الأسرار أو الكوكيز أو نص الطلبات. نجاة cleanup
وعدم تغيير المصدر جزء من شروط PASS وليسا تنظيفًا اختياريًا.

اختبارات الحراسة دون Docker:

    python -W error::ResourceWarning -m unittest discover -s tests -p 'test_operator_compose_contract.py' -v

النتيجة تخص SHA محددة وبيئة runner محددة؛ Dockerfile لا يثبت
صور الأساس أو حزم apt ببصمات كاملة. لا يغطي المجس فقد الكهرباء،
استعادة Postgres، صلاحيات مشاريع متعددة أو النشر العام. المراجعة البشرية اختيارية ولا يُعلن اجتيازها إن لم تُجرَ. لا تُعلن الحالات غير المختبرة PASS لمجرد نجاح workflow.
