# تشغيل SQLite الافتراضي للمختبر المستقل

هذه مرحلة إصلاح تشغيل، وليست واجهة مستخدم مكتملة أو اعتمادًا إنتاجيًا.
المستشفى يملك الحالات والقرارات والإغلاق. المختبر ينفذ الوصفات المعتمدة
ويصدر أدلة تنفيذ فقط؛ لا تمنحه هذه الإضافة سلطة الدمج أو النشر أو الإغلاق.

## ما يعالجه التغيير

كان compose.yaml يستخدم build: . دون Dockerfile جذري. وكان evidence وtriage
ينشئان Lab الذي يغير الصلاحيات وينشئ المخطط، رغم أن /data مقروء فقط.
أصبح البناء صريحًا بمستخدم 10001، وخدمة initialize ذات الشبكة المعطلة
تهيئ المجلد والمخطط قبل الخدمات الأربع. API والعامل فقط يكتبان بعد التهيئة.
الخدمتان القارئتان تستخدمان ReadOnlyLab: لا mkdir أو chmod أو DDL، ولا
واجهة submit/execute/reject. الاتصال mode=ro مع query_only؛ لا immutable
لأن العامل قد يحفظ أدلة جديدة. فحص صحتهما يقرأ المخطط ويعيد 503 عند تعذره.

## تشغيل محلي على Linux مع Docker Compose v2 حديث

نفذ الأوامر من نسخة Git نظيفة. يحتاج البناء شبكة لجلب صورة الأساس وGit؛
الخدمات التشغيلية على شبكة داخلية، والمنفذ الوحيد المنشور مرتبط بـ127.0.0.1.
لا تمرر رمز API إلى JavaScript أو عنوان URL، ولا تعرض هذه الواجهة للإنترنت.

```bash
# أنشئ الرمز في جلسة الطرفية؛ لا تكتبه في المستودع.
export QA_API_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
# استخدم نسخة موثوقة نظيفة خارج مستودع الخدمة، وليس شيفرة مجهولة.
export QA_WORKSPACE_PATH=/absolute/path/to/reviewed-checkout
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 120
docker compose ps
```

يرفض bind mount المسار المفقود بدل إنشاء مجلد فارغ. يجب أن تكون ملفات
النسخة قابلة للقراءة من UID 10001. يسمح Git بالمسار /workspace تحديدًا؛
لا توجد safe.directory عامة. المصدر مركب read-only ويجب أن يطابق SHA الطلب.
مجلد بيانات جديد يرث ملكية /data من الصورة. لا تعالج الخدمة تلقائيًا مجلدًا
قديمًا بملكية مختلفة، ولا تنفذ chmod/chown شاملًا لبيانات مستخدم موجودة.

نقطة الدخول الحالية http://127.0.0.1:8765 هي API وليست بوابة تسجيل دخول.
تتوفر /healthz و/v1/runs و/v1/runs/{id} و/v1/evidence/{id} و/v1/triage/{id}.
تحتاج عمليات المجال Authorization: Bearer. لا تعني صحة بصمة إيصال
توثيق المضيف أو قبول الإصدار. QA_API_PORT اختياري لتغيير المنفذ المحلي.

`docker compose down` يوقف الخدمات دون حذف البيانات. لا تستخدم `down -v`
مع بيانات تريد الاحتفاظ بها. مجس القبول وحده يحذف أحجام مشروعه الاصطناعي.

## القبول الآلي

```bash
python -W error::ResourceWarning -m unittest discover -s tests -p 'test_root_stack*.py' -v
QA_ROOT_STACK_OPT_IN=isolated-ci python scripts/verify_root_stack.py --output /tmp/qa-root-proof/receipt.json
```

المجس يتطلب شيفرة ملتزمة نظيفة وDocker محليًا عبر Unix socket، ويرفض
الدليل داخل المصدر والسياق البعيد. ينشئ مشروع Compose باسم عشوائي ونسخة
Git خاصة، ويشغل البناء من الجذر على حجم جديد: إرسال python-smoke، تنفيذ
العامل، إعادة مفتاح التكرار، رفض محتوى مختلف، قراءات HTTP بين الخدمات،
رفض الكتابة على mount وعلى اتصال SQLite، ورفض SHA غير مطابق. ثم يعيد
تشغيل الخدمات ويتحقق من نفس الإيصال وينظف موارده. يسجل SHA والشجرة
وبصمة الإيصال وإصدارات الأدوات ومعرفات الصور، ولا يصدر الرمز أو القاعدة.
هذا المجس ليس نسخًا احتياطيًا أو اختبار فقد طاقة؛ وقد تبقى صور البناء في
ذاكرة Docker المؤقتة. الصور الأساسية وحزم النظام غير مثبتة ببصمة، فلا
ندعي بناءً قابلًا للتكرار بالبايت. ينفذ CI الاختبار ولا تكفي صحة YAML وحدها.

## الحدود والخطوة التالية

هذا المسار يقيس python-smoke فقط. python-compile القديم يحتاج مراجعة
كتابة ملفات pyc عند استخدام workspace مقروء فقط، وليس وصفة معتمدة بهذا
القياس. PostgreSQL وNATS والصوت والمعرفة تبقى مسارات منفصلة دون تغيير.
لا تشغيل لشيفرة غير موثوقة، ولا إضافة وصفات عامة أو بيانات Railway.

الترتيب التالي للمنتج: هوية وجلسات وصلاحيات مشاريع في المستشفى، ثم واجهة
إرسال ومتابعة الأدلة عبر ربط خلفي لا يكشف رمز المختبر للمتصفح، ثم عقد API
واختبارات المتصفح والتشغيل والاستعادة. لا تمنح حالة PASSED للمختبر سلطة
قبول المشروع، ولا تُغلق الملاحظة التاريخية DB-OBS-001 بهذا الإصلاح.
