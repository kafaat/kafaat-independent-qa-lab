# تحقق بيانات الاستشعار عن بعد — أداة مختبر بحثية مستقلة

هذه إضافة بحثية للمختبر المستقل، مشتقة من الدلتا المرفقة بتاريخ 30 أكتوبر
2026 مع إصلاحات مثبتة باختبارات. تفحص ملفات محلية، وتنتج إيصالًا مرتبطًا
ببصمات الشيفرة والمدخلات. لا تغيّر خدمات الإنتاج أو تصحح الصور آليًا.

## التشغيل

استخدم Python 3.12 وبيئة منفصلة. تثبيت الاعتماد قد يحتاج الشبكة؛ تشغيل
الاختبارات بعد التثبيت يعمل على الملفات المحلية فقط.

```bash
python3.12 -m venv /tmp/eo-validation-venv
/tmp/eo-validation-venv/bin/python -m pip install -r tools/eo-validation/requirements.txt
PYTHONDONTWRITEBYTECODE=1 /tmp/eo-validation-venv/bin/python -B -W error::ResourceWarning tools/eo-validation/run_checks.py --output-dir /tmp/eo-validation-run-001
```

على Linux x86_64 مع CPython 3.12، يمكن تثبيت العجلة المراجعة ببصمتها:

```bash
/tmp/eo-validation-venv/bin/python -m pip install --require-hashes --only-binary=:all: --index-url https://pypi.org/simple -r tools/eo-validation/requirements-ci.txt
```

هذا هو مسار التثبيت المستخدم في CI. تثبيت الاعتماد منفصل عن تنفيذ الفحوص
المحلية. تتطلب الأداة Python 3.12 وNumPy 2.5.4، وتمنع التشغيل عند اختلافهما.

يجب أن يكون مجلد النتائج جديدًا وخارج هذه الحزمة. لا يعاد استخدام نتائج
تشغيل سابق. يخرج الأمر برمز0 عند نجاح جميع الفحوص، و1 عند فشلها، و2 عندما
تمنع المدخلات أو البيئة بدء التشغيل. تحفظ السجلات ونتيجة JSON في مجلد النتائج.
الحالة `PASSED_OFFLINE_RESEARCH_ONLY` لا تعني اعتماد الإنتاج.

## ما تضيفه الدلتا

- حارس يقارن هوية المنتج والشبكة والتحجيم والأقنعة، ويعرض فرضيات التحويل
  بصورة تشخيصية دون اعتماد إزاحة موحدة لجميع منتجات Element84.
- ثلاث نوافذ يمنية محفوظة من تاريخَي21مارس و6ديسمبر2022، مع بياناتها
  الوصفية الأصلية. ليست حدود مزرعة المستخدم أو عينة ممثلة لزراعة اليمن.
- 26 اختبار وحدة و18 فحصًا مستقلًا، تشمل رفض اختلاف شبكة SCL والمنتج،
  وتعارض CRS المعلن على الأصول، وNoData والمقام الصفري والدعم العددي الفارغ.
- 12 اختبارًا لبوابة التشغيل، تشمل نسخًا سلبية مقصودة تثبت رفض العدد الناقص
  وتجاوز الاختبارات وإيصالات النتائج المتناقضة والملفات غير المغطاة بالبيان.
- بيان SHA256 للتحقق من ثبات الشيفرة والمدخلات قبل التشغيل وبعده.

الحارس يفصل الانعكاسية السالبة عن NoData ويحتفظ بقيم NDVI خارج[-1،1].
عدادات الجودة متداخلة؛ قناع السحب لا يطبّق تلقائيًا على جميع المقارنات.
المقارنة مع تمثيل C1 اختبار اتساق، وليست تحققًا إشعاعيًا مستقلًا.

## إصلاحات المراجعة وبوابة القبول

أُثبتت الفجوات على نسخ معزولة من الحزمة الأصلية قبل الإصلاح. يتحقق الحارس
الآن من CRS الخاص بكل أصل، ويرفض الأعداد الصحيحة الضخمة التي لا تمثل قيمة
منتهية، ويرفض الفيضان في تحويل الانعكاسية أو حساب NDVI والبواقي. الرفض عبر
CLI يعيد JSON ورمز 2 بدل traceback أو استنتاج تطابق من قيم NaN.

تتحقق البوابة من هويات الاختبارات الستة والعشرين وعددها ونتائجها، ومن عدم
وجود skips أو أخطاء موارد غير معالجة. تتحقق أيضًا من أسماء الفحوص المستقلة
الثمانية عشر وعدم تكرارها ونجاح كل صف وبصمة الحارس. لا تكفي قيمة
`all_passed=true` وحدها لإعلان النجاح. العدد الصفري كان مرفوضًا في البيئة
الأصلية أصلًا؛ العيوب المثبتة كانت في العدد الناقص والاختبارات المتجاوزة.

يغطي manifest جميع ملفات الحزمة عدا نفسه، وتُقارن بايتاته وبصمات الملفات
قبل التنفيذ وبعده. تنشأ ملفات التجارب المؤقتة خارج الحزمة وتُنظف بعد الفحص.
هذه قواعد اتساق لشفرة ومدخلات مراجعة؛ ليست توقيع ثقة أو عزلًا لشفرة عدائية.

لإعادة اختبار بوابة التشغيل نفسها:

```bash
PYTHONDONTWRITEBYTECODE=1 /tmp/eo-validation-venv/bin/python -B -W error::ResourceWarning -m unittest discover -s tools/eo-validation -p 'test_run_checks.py' -v
```

## الإيصال وCI

يحفظ `result.json` معرف تشغيل مستقلًا، والأزمنة، والأوامر وأكواد الخروج،
والعدد الفعلي للاختبارات، وبصمات السجلات والمدخلات والمصدر. يسجل رأس Git
وشجرته وحالة التعديلات منفصلةً عن بصمة بايتات الحزمة؛ لا ينسب تشغيل نسخة
معدلة إلى التزام نظيف. بيانات CI المسموح بها، عند وجودها، تعريف للسياق
المعلن وليست شهادة عن هوية المضيف.

المسار `.github/workflows/eo-offline-validation.yml` يعمل يدويًا أو على
طلبات السحب التي تمس هذه الحزمة أو ملف workflow نفسه. يثبت الاعتماد ببصمته،
ويختبر البوابة، ويشغّل الفحوص، ويرفق السجلات والإيصالات. لا يسجّل وصفة في
العامل ولا يضيف مسار API ولا يغيّر قائمة الاختبارات الافتراضية للتطبيق.

## الربط المقترح بالمشاريع

**المختبر:** يشغّل الأمر أعلاه كفحص مستقل، ويجمع `result.json` والسجلات
مع معرف التشغيل ورأس الشيفرة الفعلي. يمنع الانتقال إذا كان رمز الخروج غير0.

**سهول:** تضاف الحزمة أولًا كاختبار مرجعي. يجب مراجعة شيفرة الاستيعاب الحالية
قبل توصيل الحارس أو تعديل سياسة التحجيم. لا يوجد في هذه الدلتا تغيير لمسار
FastAPI أو PostGIS أو حساب المؤشر في التطبيق.

**المستشفى:** حالات مرشحة للتشخيص: تكرار الإزاحة، اختلاف محاذاة SCL، نجاح
كاذب عند انعدام البيانات الصالحة، أو قص NDVI الذي يخفي البواقي. لا تسجّل
هذه الحالات عيوبًا مثبتة في سهول قبل فحص شيفرته؛ يرفق إيصال الاختبار عند
معالجة حالة مثبتة.

**المصنع:** يعاد استخدام أمر التشغيل ونمط الإيصال لاحقًا. لا تنسخ قواعد
Sentinel-2 المتخصصة إلى قلب المصنع، ولا تعتبر هذه الحزمة إطار تحقق عامًا.

## الحدود

هذه ليست قياسات زمن استجابة سهول، ولا اختبارًا لـCDSE أو PostGIS أو الشبكة.
لا تشمل الحزمة المصغرة قياسات VRT والتجميع السابقة؛ تبقى في حزمة الأدلة
الأصلية. اختُبر تطبيق الدلتا على فرع مستقل من المختبر بعد دمج أدلة PCM.
الربط بخدمات سهول أو العامل المنشور يحتاج اختبار تكامل منفصلًا.
ملفات المصدر والعينات ذات البصمات تمنع التغير العرضي؛ البيان ليس توقيع ثقة
ولا تدقيقًا أمنيًا شاملًا للمدخلات غير الموثوقة.

المصدر: Contains modified Copernicus Sentinel data (2022), accessed through
Element84 Earth Search. تتضمن ملفات `old_item.json` و`c1_item.json` هوية
المنتج وعناوين الأصول التي اشتقت منها النوافذ؛ لا تمثل الإضافة تأييدًا من المزود.

تفاصيل المصدر والنسب وحدود تفسير scale/offset وإصدار المجموعة موثقة في
[DATA_SOURCES.md](DATA_SOURCES.md). عينة ديسمبر من baseline 05.09 في API v1؛
لا تُنسب نتائجها إلى مجموعة v2 الحالية. فرضية التحجيم دون إعادة الإزاحة
تشخيص لهذه الأصول المحددة، وليست إذنًا بتغيير سياسة سهول عالميًا.
